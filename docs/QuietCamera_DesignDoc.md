この設計書を AI コーディングツール（Muse 等）に渡して実装させる場合、以下を守らせる。

3. **ライブラリのバージョンは `libs.versions.toml`（Version Catalog）で一元管理**し、作成時点の最新安定版を使う。
4. **各フェーズの終わりに** 「ビルドが通る」「実機での確認手順」「未解決の問題」を報告させる。
5. **【要検証】項目は断定して実装しない。** まず検証コード（ログ出力）を書き、結果を見てから実装を決める。
6. **仕様が曖昧なときは【仮決定】として進め、報告に明記する。** 黙って仕様を増やさない。
7. **Apple の素材は使わない**（ロゴ、SF Symbols、SF Pro フォント、Apple のシステム音）。代替は 3.1 を参照。
8. **非スコープ（1.3）の機能は実装しない。**

## 1. プロジェクト概要

### 1.1 コンセプト

iPhone 標準カメラの UI・UX を可能な限り忠実に再現した Android 向けカメラアプリ。見た目だけでなく、撮影操作、アニメーション、シャッター音、フォーカス、ズームなど、**カメラを使うときの体験全体**を再現する。

- iPhone のように直感的に操作できる
- シンプルで洗練されたデザイン
- 撮影時のレスポンスが速い
- シャッター音が極めて控えめ
- 日常的に使える実用性
- 不要な機能を排除した静止画特化設計

### 1.2 開発優先順位

1. 撮影品質と撮影速度
2. iPhone に近い UI・UX
3. シャッター音と操作感
4. カメラ制御の充実
5. 安定性と省電力性

### 1.3 スコープ

**実装する（In scope）**

- 静止画撮影（JPEG）、背面／前面カメラ、ズーム、タップフォーカス、露出補正、フラッシュ、タイマー、グリッド、水準器、アスペクト比切替、撮影品質切替
- 独自シャッター音と触覚フィードバック
- MediaStore への保存と、撮影直後のサムネイル更新
- ロック画面からの起動（Reno7 A のクイック起動に割り当てて使う）。ロック画面の上に表示し、解除せずに撮影できる状態を目指す

**実装しない（Out of scope）**

- 動画、Live Photos、シネマティック、ポートレート、パノラマ、スローモーション、タイムラプス
- 連写（バースト）、RAW(DNG) 撮影、独自の HDR 合成・夜景合成
- アプリ内の本格的な写真編集、クラウド連携、ストア配布
- システムが鳴らす撮影音を回避・改変する処理（5 章を参照）

※ スコープ変更（2026-11-13、ユーザーの要望による）: 当初 Out of scope だった
「連写（バースト）」と「動画」を実装する。連写はシャッター長押し（400ms〜、
離すまで連続撮影）。動画は PHOTO/VIDEO モード切替、音声なし（マイク権限を
要求しない）、最高画質設定で写真と同じ DCIM/QuietCamera へ MP4 保存とする。

## 2. 前提・制約

### 2.1 対象端末

| 項目 | 内容 |
|---|---|
| SoC / RAM | Snapdragon 695 / 6GB |
| ディスプレイ | AMOLED、最大90Hz |
| 背面カメラ | メイン・超広角・マクロ（画素数・画角・利用可否は Phase 0 で実測） |
| OS | 発売時は Android 11。SIMフリー版は Android 13 へ更新された実績がある。**キャリア版・個体によって異なり得るため、実機の Android バージョンを必ず確認する** |

### 2.2 OS バージョン別の方針【仮決定】

`minSdk = 30`、`targetSdk` / `compileSdk` は作成時点の最新安定版。UI 効果は OS で段階的に落とす。

| OS | Liquid Glass 風 UI の実装 |
|---|---|
| API 33 以上 | AGSL を使った屈折つきガラス表現（サードパーティ実装を利用可） |
| API 31〜32 | 背景ブラー + 半透明 tint（`RenderEffect` ブラーまたは Haze 等） |
| API 30 | ブラーなし。暗色の半透明塗り + 細い境界線 |

### 2.3 Phase 0 で必ず調べること【要検証】

カメラ周りは「やってみないと分からない」点が多い。設計の前提を固めるため、**最初に能力調査用の最小アプリ（またはログ出力）を作り、結果を本書に反映する。**

- 実機の Android バージョン / ビルド番号
- `CameraManager.cameraIdList` と各 ID の `LENS_FACING`、`LOGICAL_MULTI_CAMERA` 対応、物理カメラ ID
- `CameraInfo.zoomState`（minZoomRatio / maxZoomRatio）。**minZoomRatio が 0.6 前後なら超広角（0.6x）が使える。1.0 なら CameraX の通常選択では使えない。maxZoomRatio が純正と同じ 6.0 前後かも確認する**
- `exposureState`（補正範囲とステップ）
- 対応ハードウェアレベル、JPEG の出力解像度一覧（4:3 / 16:9）
- 前面カメラの出力解像度、フラッシュの有無
- CameraX Extensions（HDR / Night 等）の対応状況
- **システム側の撮影音が鳴るか**（アプリ側で一切音を鳴らさずに撮影し、実際に聞いて確認する）
- 振動モーターで `EFFECT_TICK` / `EFFECT_CLICK` が弱いクリックとして感じられるか
- **ロック画面からの起動**【要検証】
  - クイック起動に自作アプリを割り当てられるか（確認済み：任意のアプリを選べる）
  - ロック状態で起動したとき、ロック解除を求められずにプレビューが出るか
  - 暗証番号・指紋認証を設定している状態でも同じか
  - 起動からプレビュー表示までの時間

## 3. デザイン仕様

### 3.1 デザイン原則

iPhone 17 / iOS 26 の標準カメラを参考に、レイアウト・操作感・デザイン思想を独自実装する。

- Liquid Glass 風の半透明 UI（**小さな浮遊要素とパネルに限定**する）
- ミニマルなアイコン、黒を基調とした撮影画面
- 滑らかなアニメーション、直感的な操作体系
- 適切な余白と視覚的階層

**権利面の注意【確定】**

| Apple の素材 | 代替 |
|---|---|
| ロゴ・アイコン類 | 使用しない |
| SF Symbols | Material Symbols（Rounded、細め）または自作ベクター |
| SF Pro フォント | 端末標準フォント（Roboto / Noto Sans JP）。必要なら OFL ライセンスのフォント |
| シャッター音・システム音 | 使用しない（5 章の独自音） |

### 3.2 画面構成

iPhone の標準カメラは、4:3 では上下に黒帯があり、そこに操作系が置かれる。Reno7 A の縦長ディスプレイ（20:9）でも同じ構成になるため、**プレビューはアスペクト比に応じて配置する**【仮決定】。

| アスペクト比 | プレビュー配置 |
|---|---|
| 4:3（既定） | 上部バーと下部コントロールの間に配置。余白は黒 |
| 16:9 | 上部バーの下まで拡張。操作系はプレビューに重ねる |
| 1:1 | 中央に正方形で配置 |

| 領域 | 配置・機能 |
|---|---|
| 上部左 | フラッシュ（タップで AUTO / ON / OFF のメニュー） |
| 上部中央 | 撮影設定パネルを開閉するシェブロン（︿）【仮決定】 |
| 上部右 | アプリ設定画面を開く（歯車）【仮決定】 |
| 中央 | カメラプレビュー |
| プレビュー下 | ズーム倍率セレクタ（ガラスのピル型） |
| 左下 | 最近撮影した写真のサムネイル |
| 中央下 | シャッターボタン |
| 右下 | 前面／背面カメラ切替 |
| 最下部 | `PHOTO` 表示 |

**共通仕様**

- 端末の向きが変わったとき、画面自体は縦固定のまま、**アイコン類のみ回転**させる（iPhone 同様）
- 前面カメラのパンチホールを避けるため、`WindowInsets.displayCutout` / システムバーのインセットを考慮する
- カメラ画面表示中は画面を消灯させない（`FLAG_KEEP_SCREEN_ON`）

### 3.3 数値の目安【仮決定】

実機で見ながら調整する前提の初期値。

| 要素 | 値 |
|---|---|
| 背景色 | `#000000` |
| アクセント（フォーカス枠・水準器一致・ズーム選択中） | `#FFD60A` |
| ガラスの tint | 白 α 0.12〜0.20 + ブラー |
| タッチターゲット | 最小 48dp |
| ズームピル | 高さ 36dp、各ボタン直径 32dp |
| ズームピルの表示例 | `.6`　`1×`　`2` （iPhone 同様に、整数以外は小数点以下のみ表示）【仮決定】 |
| フォーカス枠 | 約 72dp の角丸四角（黄色） |
| サムネイル | 約 48dp、角丸 8dp |
| シャッターボタン外径 | 76dp（4.1 を参照） |

### 3.4 アニメーション【仮決定】

| 動作 | 内容 |
|---|---|
| シャッター押下 | 内側円が 0.92 倍へ（スプリング、約 80〜100ms）。**撮影処理を待たせない** |
| 撮影確認 | プレビューを一瞬だけ暗くする（約 80ms）。音が小さい分、視覚で撮影を確認できるようにする |
| ズーム切替 | 約 250ms でなめらかに補間 |
| フォーカス枠 | 1.3 倍 → 1.0 倍へ縮小（約 200ms）→ 約 1.5 秒表示 → フェードアウト（約 300ms） |
| 設定パネル | 約 300ms のスプリングで展開 |

### 3.5 プレビューとガラス効果の関係【要検証】

`PreviewView` の既定（`PERFORMANCE` モード）は `SurfaceView` を使い、**Compose 側のブラーやバックドロップ効果の対象にならないことがある**。ガラス表現でプレビューの映像をぼかしたい場合は、`COMPATIBLE`（`TextureView`）モード、または `CameraXViewfinder` の埋め込みモードの利用を検討する。

- 4:3 では操作系の大半が黒帯の上にあるため、ガラス効果が必要なのは主にズームピルと設定パネル
- 効かない・重い場合のフォールバック: ブラーなしの暗色半透明パネル（2.2 の API 30 相当）

## 4. UI コンポーネント詳細

### 4.1 シャッターボタン

| 項目 | 仕様 |
|---|---|
| 外径 | 76dp |
| 構成 | 外周の白リング（太さ約 4dp）+ 隙間（約 4dp）+ 内側の白い円（直径約 60dp）【仮決定】 |
| 押下時 | **内側円**が 0.92 倍に縮小（リングは固定）【仮決定】 |
| 撮影トリガー | 指を離した瞬間（iPhone 準拠）【仮決定】 |
| 音 | 独自の控えめな効果音（5 章） |
| 振動 | 弱い触覚フィードバック（5 章） |

**処理順序**

1. 指を離す
2. 即座に縮小アニメーション開始 + 効果音・触覚を再生（並行）
3. `ImageCapture.takePicture()` を実行
4. 保存完了のコールバックで内側円を通常サイズへ戻し、サムネイルを更新

アニメーションや効果音の再生で、撮影処理を遅らせないこと。

### 4.2 ズーム操作

倍率ボタンは**実機が報告するズーム範囲から動的に生成**する。

| 倍率 | 想定 | 備考 |
|---|---|---|
| 0.6x | 超広角 | 純正カメラでは 0.6x として提供されている。`minZoomRatio ≤ 0.6` のときのみ表示。使えない場合はボタン自体を出さない【要検証】 |
| 1x | メインカメラ | |
| 2x | メインのデジタルズーム | 光学相当ではなくクロップ+拡大。画質は 1x より劣る前提 |
| 最大 6x | デジタルズーム | 純正は 1〜6x。ピンチ・ダイヤルの上限は端末が報告する `maxZoomRatio`（目標は 6x） |

**操作**

- 倍率ボタンのタップで切替（滑らかに補間）
- ピンチイン・アウトで連続ズーム
- ズームボタンの長押しで**ズームダイヤル**を表示し、スライドで連続ズーム（iPhone 準拠）【仮決定】
- 現在倍率がボタンと一致しない中間値のときは、選択中のボタンに現在値（例：`1.7×`）を表示する

> 超広角が標準の背面カメラ選択に含まれず、独立したカメラ ID としても見えない場合、**0.6x は実装しない**。純正カメラで使えることと、サードパーティ製アプリに開放されていることは別なので、Phase 0 で確認する。非公開 ID の直接オープンは不安定なので要件に含めない。

### 4.3 撮影設定

| 設定 | 選択肢 |
|---|---|
| フラッシュ | AUTO / ON / OFF（前面は画面フラッシュ） |
| タイマー | OFF / 3秒 / 10秒 |
| 露出 | 端末が報告する補正範囲内（目標は -2.0〜+2.0 EV） |
| アスペクト比 | 4:3 / 16:9 / 1:1 |
| グリッド | ON / OFF |
| 水準器 | ON / OFF |
| 撮影品質 | 標準 / 高画質 |

設定パネルは半透明の Liquid Glass 風デザイン（2.2 の OS 別方針に従う）。

### 4.4 フォーカスと露出

- プレビューのタップで、その位置にフォーカス + 測光（AF / AE / AWB）
- フォーカス位置にアニメーション付きの黄色い枠と、隣に太陽アイコンの露出スライダーを表示
- タップ位置から上下ドラッグで露出補正を変更
- **長押しで AE/AF ロック**（iPhone 同様、両方を同時にロック）。画面上部に「AE/AF ロック」表示を出す【仮決定】
- AE と AF を**個別にロックする機能は初期実装に含めない**（iPhone 標準にもなく、Camera2 Interop が必要）。Version 1.x の候補とする

### 4.5 タイマー

- 3秒 / 10秒。カウントダウンの数字を画面中央に大きく表示
- 1秒ごとに弱い触覚フィードバック
- カウント中のシャッターボタン再タップ、または専用ボタンでキャンセル

### 4.6 グリッドと水準器

- グリッド: 3×3 の細い白線（α 0.4 程度）
- 水準器: `SensorManager`（`TYPE_ROTATION_VECTOR` または `TYPE_GRAVITY`）で端末の傾きを取得し、水平線を表示。傾きが約 1° 以内に収まったら黄色にする【仮決定】

### 4.7 前面カメラ

- プレビューはミラー表示。**保存画像のミラーは設定で切替**（既定は非ミラー）【仮決定】
- フラッシュは画面フラッシュ（画面を白くして輝度を上げる）。CameraX の画面フラッシュ機能（CameraX 1.4 以降）を利用する

### 4.8 ロック画面からの起動

Reno7 A のクイック起動に本アプリを割り当て、ロック画面から素早く撮影できるようにする。【確定】

**マニフェスト設定**

```xml
<activity
    android:name=".MainActivity"
    android:exported="true"
    android:showWhenLocked="true"
    android:turnScreenOn="true"
    android:screenOrientation="portrait">

    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>

    <!-- カメラ起動用（OS やショートカットが探す） -->
    <intent-filter>
        <action android:name="android.media.action.STILL_IMAGE_CAMERA" />
        <category android:name="android.intent.category.DEFAULT" />
    </intent-filter>
    <intent-filter>
        <action android:name="android.media.action.STILL_IMAGE_CAMERA_SECURE" />
        <category android:name="android.intent.category.DEFAULT" />
    </intent-filter>
</activity>
```

**ロック中の動作【仮決定】**

| 項目 | 仕様 |
|---|---|
| 判定 | `KeyguardManager.isKeyguardLocked` でロック中かを判定する |
| 撮影・保存 | 通常どおり可能（MediaStore へ保存） |
| サムネイルのタップ | ロック中は無効にする（写真アプリを開かない） |
| 設定（歯車） | ロック中は無効にする |
| 画面が消えたとき | ロック中に画面が消灯したら、アプリを終了する |
| 起動速度 | 起動処理を最小限にし、プレビュー表示までの目標を 1.5 秒以内とする |

**フォールバック**

ロック画面の上で起動できない、またはロック解除を毎回求められる場合は、次の順で対応する。

1. 解除後に起動する運用（クイック起動 → 解除 → 撮影の 2 ステップ）で許容する
2. クイック設定タイル（`TileService`）を追加し、ロック画面のクイック設定から起動する

## 5. シャッター音・触覚の設計

### 5.1 コンセプト

本アプリの独自仕様。大きな機械音ではなく、iPhone の Live Photos 撮影時のような、**極めて控えめな柔らかい電子クリック**を目指す。

| 項目 | 仕様 |
|---|---|
| 音の長さ | 30〜100ms（初期目安 60ms） |
| 音量 | 小さく、耳障りでない |
| 音質 | 柔らかい電子クリック。余韻はほぼなし |
| 振動 | 弱いクリック感 |

### 5.2 実装方法

**音**

- 独自に制作した効果音（Apple の音源は使用しない）。生成スクリプト例を付録 A に掲載
- 形式: WAV（16bit PCM、モノラル、48kHz）
- `SoundPool` で起動時に事前ロードし、ロード完了（`OnLoadCompleteListener`）を確認してから再生可能にする
- `AudioAttributes` は `USAGE_ASSISTANCE_SONIFICATION` / `CONTENT_TYPE_SONIFICATION`
- 再生は**シャッターを離した瞬間**（4.1 の処理順序の手順 2）。CameraX の撮影開始コールバックが利用できるバージョンなら、そちらへの同期も検討する【要検証】
- マナーモード時の挙動は設定で選べるようにする（既定：鳴らさない）【仮決定】

**触覚**

- `VibratorManager` / `Vibrator` を直接使い、`VibrationEffect.createPredefined(EFFECT_TICK)` を優先
- 端末が弱いクリックを表現できない場合は、短い `createOneShot`（10〜20ms、低振幅）へフォールバック
- Compose の `HapticFeedback` は種類が限られるため、本アプリでは使わない
- 音と触覚は**個別に ON/OFF**できる

### 5.3 システム側の撮影音について

日本向け Android 端末では、メーカーや OS によって撮影音が強制されることがある。一般に Camera2 系 API（CameraX を含む）は、フレームワークが自動で撮影音を鳴らすことはなく、鳴らす責任はアプリ側にあるが、**OPPO Reno7 A でそうなっているかは実機でしか分からない**。

- Phase 0 で「アプリが無音で撮影したとき、システム音が鳴るか」を確認する【要検証】
- システム音が鳴る場合でも、回避は要件に含めない。独自音は鳴らさず、状況を記録して仕様を見直す
- **音を完全に消すことは目的としない。** 控えめに鳴らす方針を維持する。人物を撮る場面では、場所のマナーや地域のルールに配慮する

## 6. 技術アーキテクチャ

### 6.1 全体構成

```
Presentation Layer   … Jetpack Compose / UiState / Animation
        │
        ▼
Domain Layer         … 撮影ロジック / 設定（薄く保つ）
        │
        ▼
Data Layer           … CameraX / Camera2 Interop / MediaStore / SoundPool / DataStore
        │
        ▼
Android Hardware     … カメラセンサー / フラッシュ / 振動モーター
```

- UI とカメラ処理を分離し、将来の機能変更に対応できる構成にする
- Domain 層は現状ほぼ素通りになるため、**UseCase は必要になった時点で追加**し、最初は ViewModel → CameraController の直接呼び出しでよい【仮決定】
- 状態は `StateFlow<CameraUiState>` に集約し、UI は一方向データフローで描画する

| Kotlin / Coroutines / Flow | 言語・非同期処理 |

### 6.3 機能と API の対応

| 前面ミラー保存 | `ImageCapture.Metadata` の `isReversedHorizontal` | |
| 詳細制御 | Camera2 Interop（ノイズ低減・エッジ・トーンマップ） | 【要検証】 |

## 7. 写真の保存・ギャラリー

### 7.1 保存仕様

| 項目 | 内容 |
|---|---|
| 保存場所 | `DCIM/QuietCamera`（`MediaStore.Images.Media.RELATIVE_PATH`） |
| ファイル形式 | JPEG |
| ファイル名 | `IMG_YYYYMMDD_HHMMSS`。同一秒の重複は連番サフィックスを付与（例：`_001`）【仮決定】 |
| EXIF | 撮影日時・向きなど。**位置情報は既定でオフ**（設定で有効化した場合のみ位置情報の権限を要求）【仮決定】 |
| 閲覧 | Android 標準の写真アプリから閲覧可能 |
| サムネイル | 撮影直後に更新 |

- MediaStore を使用し、書き込み中は `IS_PENDING` を使う
- Android 10 以降では、自分のアプリが作成した写真の保存にストレージ全体へのアクセス権限は原則不要

### 7.2 撮影後の挙動

1. シャッターを離す
2. 撮影処理を実行
3. 写真を MediaStore に保存
4. 保存結果の URI から左下のサムネイルを更新
5. 撮影画面に留まったまま、次の写真を撮影できる

撮影のたびに別画面へ遷移させない。

### 7.3 サムネイルとギャラリー【仮決定】

- サムネイルは「**自アプリで撮影した最新の写真**」とする（ライブラリ全体を読むと読み取り権限が必要になるため）
- サムネイルのタップは、**初期は標準の写真アプリへ URI を渡して開く**（`ACTION_VIEW`）。アプリ内 `GalleryScreen` は将来の拡張とする
- サムネイルの読み込みは `ContentResolver.loadThumbnail` 等で、画像を大量にメモリへ保持しない
- アプリを再インストールした後は、過去に自アプリで保存した写真が見えなくなる場合がある。その場合のみ、画像の読み取り権限の追加を検討する

## 8. 画質方針

純正カメラアプリには、メーカー独自の画像処理（HDR・ノイズ除去・色調整・夜景合成など）が組み込まれている可能性があり、CameraX で同じセンサーを使っても、**同じ画質が得られるとは限らない**。UI の再現度と画質は別々に評価する。

### 8.1 画質に影響する設定【要検証】

| 設定 | 内容 |
|---|---|
| キャプチャモード | 標準 = `CAPTURE_MODE_MINIMIZE_LATENCY`、高画質 = `CAPTURE_MODE_MAXIMIZE_QUALITY`。ゼロシャッターラグ（`CAPTURE_MODE_ZERO_SHUTTER_LAG`）は対応端末のみ |
| JPEG 品質 | 標準 = Q90、高画質 = Q97 を初期値とし、実機で調整【仮決定】 |
| 解像度 | `ResolutionSelector` で目的の出力サイズを選択（候補は Phase 0 の一覧から） |
| Extensions | 端末が HDR / Night 等に対応していれば利用を検討 |
| Camera2 Interop | ノイズ低減・エッジ強調モードを「高品質」に設定して比較 |

### 8.2 純正カメラとの比較方法

同じ条件（可能なら三脚、同じ場所、同じ時刻）で純正アプリと本アプリを撮影し、以下を比較する。

| シーン | 見るポイント |
|---|---|
| 晴天の屋外 | 解像感、色、ダイナミックレンジ |
| 逆光 | 白飛び・黒つぶれ |
| 室内の暗所 | ノイズ、ブレ、色かぶり |
| 2x（デジタルズーム） | 解像感の差 |
| 超広角（使える場合） | 周辺の歪み・解像感 |

## 9. OPPO Reno7 A 向け最適化

### 9.1 最適化方針

| 項目 | 方針 |
|---|---|
| UI | 60fps 以上を目標。ガラス効果が重い場合は 2.2 の下位ティアへ落とす |
| プレビュー | 端末に適した解像度 |
| 撮影 | 画質・速度を実機で比較 |
| メモリ | 画像を大量に保持しない |
| サムネイル | 遅延読み込み |
| バッテリー | 非表示時にカメラを停止（ライフサイクル連動） |

### 9.2 性能目標【仮決定・実機で見直す】

| 指標 | 目標 |
|---|---|
| コールドスタート → プレビュー初フレーム | 1.5 秒以内 |
| シャッターを離す → 効果音再生 | 50ms 以内 |
| シャッターを離す → 保存完了（標準品質） | 1.5 秒以内 |
| 連続撮影（保存完了を待たずに次を撮影） | UI が固まらない |
| 撮影画面での連続操作 | ジャンク（描画落ち）が目立たない |

## 11. 権限・異常系

### 11.1 権限

| 権限 | 用途 |
|---|---|
| `CAMERA` | 必須（実行時に要求） |
| `VIBRATE` | 触覚フィードバック（通常権限） |
| 位置情報 | 位置情報の付与を有効にした場合のみ |

### 11.2 異常系

| 事象 | 挙動 |
|---|---|
| カメラ権限が拒否された | 説明画面を表示し、端末の設定画面へ誘導 |
| カメラを他アプリが使用中・カメラエラー | エラー表示と再試行 |
| ストレージ不足・保存失敗 | 通知を出し、撮影画面は維持 |
| 起動直後にシャッターが押された | プレビュー開始前は撮影を受け付けない |
| 効果音のロード未完了 | 音なしで撮影を続行（撮影をブロックしない） |
| バックグラウンド移行 | カメラを解放し、復帰時に再バインド |
| ロック画面の上で起動できない・解除を求められる | 4.8 のフォールバックへ切り替える |

## 13. 品質検証・受け入れ基準

以下をすべて満たしたら完成とする。

**基本動作**

- [ ] アプリ起動後、カメラプレビューが表示される
- [ ] シャッターを押すと写真が `DCIM/QuietCamera` に保存される
- [ ] 縦・横どちらで撮影しても、写真の向きが正しい
- [ ] 撮影後も連続して撮影できる
- [ ] サムネイルが撮影直後に更新され、タップすると写真を開ける
- [ ] ギャラリー（標準の写真アプリ）に写真が表示される

**カメラ制御**

- [ ] 端末が報告するズーム倍率の範囲（目標：0.6x〜6x）で、倍率が正しく切り替わる（使えない倍率は表示されない）
- [ ] 0.6x（超広角）が使える場合、切替時に画角が実際に広がり、保存された写真も広角になっている
- [ ] タップフォーカスが機能する
- [ ] 露出調整が機能する
- [ ] アスペクト比（4:3 / 16:9 / 1:1）が保存画像に反映されている
- [ ] 前面カメラで撮影・保存できる（画面フラッシュ含む）

**シャッター体験**

- [ ] シャッターアニメーションが滑らか
- [ ] **アプリが音を出さない状態で撮影し、システム音が鳴るかどうかを確認・記録した**
- [ ] 独自効果音の長さ・音量・音質が目標範囲に収まっている（5.1）
- [ ] 触覚フィードバックが「弱いクリック」として感じられる

**ライフサイクル・永続化**

- [ ] アプリをバックグラウンドにするとカメラが解放される
- [ ] アプリの再起動後も設定が維持される
- [ ] カメラ権限の拒否・保存失敗で、アプリがクラッシュしない

**ロック画面**

- [ ] クイック起動から本アプリが起動する
- [ ] ロック状態で起動し、解除を求められるかどうかを確認・記録した
- [ ] ロック中でも撮影・保存できる
- [ ] ロック中はサムネイル・設定から写真アプリや設定画面が開かない
- [ ] ロック中に画面が消灯したら、アプリが終了する

**性能**

- [ ] 9.2 の目標値を、実機で計測して達成している（未達の場合は理由と対応を記録）

## 14. リスクと未確定事項

| リスク | 影響 | 対応 |
|---|---|---|
| システム側の撮影音が強制される | 静音の目標が達成できない | Phase 0 で検証。回避は要件外。鳴る場合は仕様を見直す |
| 超広角（0.6x）・6x が使えない | ズーム仕様の縮小 | `zoomState` の範囲で動的に表示。使えなければボタンを出さない。純正で使えても、サードパーティには開放されていない可能性がある |
| 純正より画質が劣る | 優先順位 1 を満たせない | キャプチャモード・Extensions・Camera2 Interop を比較し、実機で最良の設定を採用 |
| ガラス効果がプレビューに効かない・重い | 見た目の再現度低下 | 3.5 の対応。OS 別ティアで段階的に落とす |
| 振動モーターが弱く、クリック感が出ない | 触覚の再現度低下 | `EFFECT_TICK` / `CLICK` / 短い OneShot を比較。最悪は触覚なしでも許容 |
| 実機の OS が Android 11〜12 のまま | 一部の視覚効果が使えない | 2.2 のティアで対応 |
| 端末のバッテリー・省電力設定でカメラ起動が遅れる | 起動速度の悪化 | 実機計測。必要なら省電力の除外設定を案内 |
| iPhone の素材・意匠の扱い | 権利面 | 個人利用に限定し、Apple の素材を使わない（3.1）。配布しない |
| ロック画面の上で起動できない、または毎回解除を求められる | 優先事項（素早い起動）が満たせない | 4.8 のフォールバック（解除後の起動、クイック設定タイル）。Phase 0 で最初に検証する |

## 16. 最終的な開発方針

最も重要なのは次の 3 点。

## 付録 A：効果音の生成スクリプト例

Python（numpy）で、短い柔らかいクリック音（約 60ms）を生成する例。音は聴きながら、長さ・周波数・減衰を調整する。

```python
import numpy as np
import wave

sr = 48000
dur = 0.060                      # 60ms
t = np.arange(int(sr * dur)) / sr
rng = np.random.default_rng(0)

# 1.5〜4kHz のバンドノイズ（簡易バンドパス）
spec = np.fft.rfft(rng.standard_normal(t.size))
freqs = np.fft.rfftfreq(t.size, 1 / sr)
spec[(freqs < 1500) | (freqs > 4000)] = 0
band = np.fft.irfft(spec, t.size)
band /= np.max(np.abs(band))

tone = np.sin(2 * np.pi * 2200 * t)          # 2.2kHz のトーン
env = np.exp(-t / 0.012)                     # 速い指数減衰
attack = np.minimum(1.0, t / 0.001)          # 1ms のアタック（プチ音防止）
release = np.minimum(1.0, (dur - t) / 0.005) # 末尾 5ms のフェードアウト

sig = (0.6 * band + 0.4 * tone) * env * attack * release
sig = sig / np.max(np.abs(sig)) * 0.25       # 約 -12 dBFS
pcm = (sig * 32767).astype(np.int16)

with wave.open("shutter_soft.wav", "wb") as w:
    w.setnchannels(1)
    w.setsampwidth(2)
    w.setframerate(sr)
    w.writeframes(pcm.tobytes())
```

生成した `shutter_soft.wav` を `app/src/main/res/raw/` に置く。
