# Phase 0 調査結果（OPPO Reno7 A 実機）

設計書 2.3 の調査項目に対する実機結果をここに記録する。
アプリの調査画面（Phase 0 ビルド）が出力したテキストを貼り、耳・指で確認する項目は所見を書く。

- 実施日: 2026-11-12
- アプリ版: 0.1.0-phase0（versionCode 2）

## 端末 / OS

- OPPO CPH2353（Reno7 A）
- Android バージョン: 12（API 31）/ ビルド番号: CPH2353_11_C.28（SKQ1.220303.001）
- セキュリティパッチ: 2024-06-05
- → 設計書 2.2 の UI ティアは **API 31〜32**（RenderEffect ブラー / Haze。AGSL の屈折表現は使わない）

## カメラ構成

- cameraIdList: 2件（背面 ID 0 / 前面 ID 1）。どちらも HW レベル **LEVEL_3**
- 論理マルチカメラではない（物理 ID の公開なし）。超広角・マクロは独立カメラとして現れない
- 背面の JPEG 解像度: 4:3 は最大 **3264x2448**、16:9 は最大 3840x2160、1:1 は最大 2448x2448。フラッシュあり
- 前面の JPEG 解像度: 4:3 は最大 2304x1728、16:9 は最大 1920x1080。フラッシュなし（画面フラッシュで代替・設計書 4.7）

## ズーム・露出（CameraX）

- zoomState（背面・前面とも）: min = 1.0 / max = 6.0
- → **0.5x 超広角は利用不可**。ズームボタンは 1.0〜6.0 の範囲から生成し、0.5x は出さない
- 露出補正: 範囲 [-12, 12] / ステップ 1/6 EV（EV 換算 約 **-2.0 〜 +2.0 EV**）

## Extensions

- AUTO / BOKEH / HDR / NIGHT / FACE_RETOUCH: **すべて非対応**（背面・前面とも）
- → 画質方針（8 章）は Extensions に依存しない。キャプチャモードと Camera2 Interop の範囲で詰める

## 起動

- 通常起動 → 画面表示: **319 ms**（4.8 の目標 1.5 秒以内に対して十分速い。プレビュー表示までの計測は Phase 1 で実施）

## 実機確認（耳・指）— 確認済み（2026-11-12）

- システム撮影音: **鳴らなかった**（アプリ無音撮影でシステム音なし）→ 独自の微小音のみで運用できる。設計書 5 章の設計どおり進められる
- 振動: **EFFECT_TICK** が最も弱いクリックだった（左端のボタン。ユーザーの表現「一番左の振動」から TICK と判定）

## ロック画面からの起動（2.3 / 4.8）— 確認済み（2026-11-12）

- クイック起動への割り当て: できた
- ロック状態で起動し、解除を求められずに画面が出たか: **出ない**。指紋認証で解除した後にクイック起動が効き、解除の流れの中で上にスワイプするとアプリが開く。体感はかなりスムーズ
- 暗証番号・指紋認証を設定した状態での結果: 指紋認証ありで上記のとおり（解除が前提）
- 起動→画面表示までの時間: 解除込みの流れのため単独計測は困難（通常起動は 319 ms）
- ロック中の撮影・保存: ロック画面の上で起動できないため対象外（解除後は通常どおり可能）
- ロック中に消灯→アプリ終了: 同上、対象外
- → **設計書 4.8 のフォールバック 1（解除後に起動する運用）を採用する**
- 不具合（要対応）: アプリを開いたまま消灯し、再点灯すると、ロック画面が出ずにアプリ画面が表示される／ロック画面とアプリ画面が重なって表示されることがある。原因は `showWhenLocked` がマニフェストで常時有効なため、通常セッションでもロック画面の上に表示され得ること。対策は Phase 1 で実施する：フラグをマニフェストから外し、ロック中起動または SECURE インテントのときだけ `setShowWhenLocked(true)` / `setTurnScreenOn(true)` をプログラムで設定する

## 判定・次のフェーズへの反映

- 前提として確定: Android 12（API 31 ティア）、0.5x なし、Extensions なし、背面の最大解像度 3264x2448、露出 ±2.0 EV
- システム撮影音は強制されない。振動の既定候補は EFFECT_TICK
- ロック画面はフォールバック 1 採用（解除→クイック起動）。showWhenLocked の常時有効化による再点灯時の表示不具合は Phase 1 でプログラム制御化して直す
- **Phase 0 の完了条件（調査結果の記録・クイック起動可否の判明）を満たした**
